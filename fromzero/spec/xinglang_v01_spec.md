# 星算语 v0.1 语义规范（六智者议会收敛版）

> **版本**：v0.1 · 冻结
> **来源**：六智者议会（千问/豆包/智谱/混元/DeepSeek/Kimi）三轮流式粘贴板收敛
> **日期**：2026-09-10
> **硬约束**：32GB 内存 · 无大 GPU · CPU 存算一体
> **核心主张**：v0.1 焊死的是「可重放性」，不是接口僵化。地基歪了，楼必塌。

---

## 1. 范围与原则

本规范冻结星算语最小可执行内核 v0.1。**所有多源头实现**（C/Rust/C#/Lisp/Erlang/APL/Q#）必须：
- 服从同一套语义、字节码、资源预算、确定性验收；
- 通过同一套 golden 测试（哈希一致），否则视为未汇合；
- 任何 PR 导致峰值内存 +100MB / 单步耗时 +10% / golden 哈希不一致 → 直接打回。

**三条铁则**
1. `▸` 事件必须先于同一作用域内任何 `↦` 执行。
2. 所有资源约束不是开发者自觉遵守，是字节码级 / 编译期 / 运行时**三层强制拦截**。
3. 多线程只改执行速度，不改求值顺序——单线程与 8 线程输出**逐位相同**。

---

## 2. 三符语义（三层抽象）

三符不是语法糖，是三层 IR 的语义锚。v0.1 冻结接口签名，不实现全部逻辑。

| 符号 | 层 | v0.1 状态 | 语义 | 未来扩展 |
|------|-----|-----------|------|----------|
| `▸` 位置 | 符号层 | **noop 但接口签名冻结**，必须产生可见 trace 事件 | 位置声明 / 符号锚 / 命名空间 | 符号约束、实体锚定、稀疏化计算 |
| `↦` 变换 | 神经层 | 张量计算图 + 自动微分标准域，带 `fp32_only`/`int8_safe` 精度枚举 | 张量变换 / 梯度 / 权重更新 | 算子融合、量化路径 |
| `⟶` 流 | 流/量子层 | 块级流，**禁止全量张量驻留**；QReg 作确定性伪随机种子源 | 块流 / 概率语义 / 确定性随机 | `⟶retrieve` 检索流、量子叠加态 |

**层间调用契约（冻结）**
- `▸` 产生的符号锚必须先于 `↦` 执行；
- `↦` 的梯度回流不能绕过 `↦` 直接写 `▸` 符号表；
- `⟶` 禁止任何算子要求输入为全序列张量（编译期堵死全量驻留）。

**三符联合测试（golden 必需）**：一条用例同时包含 `▸` → `↦` → `⟶`，验证执行顺序在 C 核中确定。

---

## 3. 核心算子集（11 个）

| # | 算子 | 用途 | 资源签名要点 |
|---|------|------|--------------|
| 1 | `matmul` | 矩阵乘（分块，AVX2） | FLOPs=2·M·N·K，块读写字节 |
| 2 | `add` | 张量加 | 元素数×4B（fp32） |
| 3 | `layernorm` | 层归一化 | 每行均值/方差，块级 |
| 4 | `softmax` | 注意力 softmax（线性注意力下简化） | 块内 max/exp/sum |
| 5 | `cross_entropy` | 损失函数 | 元素数×4B |
| 6 | `QReg` 种子 | 确定性伪随机初始化 | 种子→序列映射（版本化） |
| 7 | `H` 门 | dropout 熵源 | 确定性，非运行时随机 |
| 8 | `▸` | 符号定位（noop，产生 trace） | 仅 trace 事件，零内存 |
| 9 | `↦` | 张量变换（带精度枚举） | 按精度枚举计内存/FLOPs |
| 10 | `⟶` | 块级流（禁全量驻留） | 声明读写字节数 |
| 11 | 参数更新 | AdamW（梯度检查点 + 激活重计算） | 参数+双矩+梯度 |

**精度枚举**：`↦` 算子标 `fp32_only` / `int8_safe` 两个编译期枚举值，**禁止运行时 if 动态切精度**。v0.1 主路径只走 fp32，INT8 仅做影子基准（不进 golden 主哈希，但报告量化误差上界）。

---

## 4. 字节码格式

- **1 字节操作码 + 3 字节定长操作数**（共 4 字节定长指令）。
- 头部含**三符版本号**（`▸`/`↦`/`⟶` 各自接口签名版本）。
- 定长操作数从格式上**杜绝解析歧义**。
- 每条指令对应资源签名（见 §6），可静态查表。

---

## 5. 确定性规则（归约树）

浮点不确定性是六源汇合的最大暗礁。v0.1 采用**确定性并行**，不是单线程：

- **块内**：固定**行优先累加树**；
- **块间**：固定**二叉归约树**合并；
- **绝不按线程完成顺序归约**；
- v0.1 验收铁律：单线程与 8 线程输出**逐位相同**。

多线程只改速度，不改求值顺序——逐位一致与 AVX2 多核吞吐兼得。

**QReg 种子→序列映射**：种子到伪随机序列的映射函数必须写进语义合同并**版本化**（跨实现可复现，否则 C 版与 Rust 版初始化参数不同，loss 曲线无法跨实现比对）。零成本，现在定。

## 6. 资源签名与代价语义（cost.toml）

不是软规则，是**可机器审计、可版本化的代价签名**。任何 IR 在进入 C 核前，其峰值内存 / FLOPs / 带宽 / 归约顺序 / 浮点事件序列都被静态锁定。

- **字节码级**：每条指令执行前扣减内存 / FLOPs / 带宽配额，超支直接抛确定性错误。
- **编译期**：Rust 校验器静态累加全程序资源预算，误差 >5% 编译失败。
- **运行时**：原子扣减校验，**不允许动态调配**。
- 代价表独立为 **`cost.toml`**，进入 CI 版本控制，每条指令带测量来源与日期。
- 峰值内存**内部四栏**上报：**参数 / 优化器状态 / 激活块 / 运行时**。

**误差门禁**：编译期预估 vs 实测误差 >5% 即回炉。

## 7. 内存预算（默认可配置，但经 Rust 校验）

| 区域 | 预算 | 用途 |
|------|------|------|
| 模型/数据区 | 24GB | 参数、优化器状态、训练数据 mmap、检索索引 |
| Runtime 区 | 8GB | 激活块、KV 状态块、执行缓冲 |

- 1M 参数闭环实际峰值 **≤3.5GB**（留 0.5GB 防 IO 碎片）。
- 10M 参数全量训练预计峰值 8~12GB。
- 带宽预算：数据 mmap 顺序块读，KV 固定页块（32KB），`⟶` 算子声明读写字节数。

---

## 8. Golden 测试五项哈希（全部一致才算通过）

每个测试用例必须输出五项，哈希全部一致：

1. **字节码哈希**
2. **资源预算报告哈希**
3. **执行 trace 哈希**（整数事件 + 浮点值，可重放）
4. **固定归约浮点值哈希**
5. **loss 序列哈希**

附加用例：
- **三符联合测试**：`▸` → `↦` → `⟶`，验证执行顺序确定性；
- **分块不变性测试**：同程序任意 chunk 大小（16/32/64KB）输出一致；
- **确定性并行测试**：1/2/4/8 线程逐位一致。

## 10. 版本化

- 语义合同、代价表（cost.toml）、QReg 映射函数、三符接口签名**全部进入版本控制**；
- 任何 IR 变更必须同步 bump 三符版本号；
- CI 唯一标准：跑在同一套 32GB x86 消费级 CPU 机器上。
