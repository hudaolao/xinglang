# 星算语 v0.3 · 可视化 / IO 表达算子规范(XL01 扩展)

> **里程碑**: P5 = 可视化/IO 表达补全 —— 城主早前指出"星算语没有显示图片类函数/符号, 可视化动态化要补"
> **铁则**: 可视化算子仍走统一 XL01 发射, 不平行执行栈; 既有 17 算子(1-17)语义与编号**冻结不动**; stdlib 预留 18-47, 可视化区间 **48-62**
> **版本**: v0.3 · 新增可视化/IO 算子 15 个 · 日期 2026-09-10

---

## 1. 设计哲学: 画布即位置, 读取即显示

星算语的根是**存算一体**——计算与内存是同一层。可视化不能是外挂一个"GUI 库", 否则就破了根。v0.3 把可视化收编进三符语义:

- **画布即位置(▸)**: 一块 W×H 的帧缓冲不是"外部窗口", 它就是一个 `▸` 锚定的**位置**(内存区)。像素是位置里的 cell, 写像素 = 写位置, 读像素 = 读位置。
- **画笔即状态(↦)**: 画笔颜色 / 画笔坐标是神经层(↦)的可变状态——它是变换的"当前参数", 不是外部系统状态。
- **渲染即流出(⟶)**: 把画布"显示出来" = 把这个位置的内容**流到外部输出流**(文件/流), 走 `⟶` 块级流出语义——不要求整图驻留在外部, 逐行流出。
- **读取即显示**: 传统 GPU 渲染是"画到帧缓冲→present"; 星算语里"显示"只是**把位置物化到一个 PPM 文件**, 无显示设备依赖, 纯本地, 无外部库。

这条哲学让"可视化"不是新范式, 而是三符在 IO 维度的投影: `▸`(画布位置) → `↦`(画笔变换) → `⟶`(流出渲染)。

## 3. 可视化/IO 算子表(15 个, opcode 48-62)

operand 统一为 24-bit 小端整数(3 字节), 按算子语义打包。位域记号: `[hi:lo]`。

| opcode | 名称 | operand 布局(24-bit) | 语义 | 最小管线 |
|--------|------|----------------------|------|---------|
| 48 | `vcanvas_new` | `W[11:0] << 12 \| H[11:0]` | 创建 W×H RGB 画布, 清零(黑), 置为"当前画布"。W/H ≤4095 | ✅ 实现 |
| 49 | `vpen_move` | `X[11:0] << 12 \| Y[11:0]` | 画笔坐标移到 (X,Y), 不改像素 | ✅ 实现 |
| 50 | `vpen_color` | `R[7:0]<<16 \| G[7:0]<<8 \| B[7:0]` | 设置画笔当前色 (R,G,B) | ✅ 实现 |
| 51 | `vpix_dot` | 0(忽略) | 在画笔当前位置写当前色 | ✅ 实现 |
| 52 | `vpix_at` | `X[11:0] << 12 \| Y[11:0]` | 在 (X,Y) 写当前色(画笔位置不变) | ✅ 实现 |
| 53 | `vpix_read` | `X[11:0] << 12 \| Y[11:0]` | 读 (X,Y) 像素 → 产生 trace 事件(不改画布, 不改画笔) | ✅ trace |
| 54 | `vfill_rect` | `X0[11:0] << 12 \| Y0[11:0]` | 用当前色填充矩形: 左上 (X0,Y0), 右下 = 画笔当前位置 (含端点) | ✅ 实现 |
| 55 | `vfill_all` | 0(忽略) | 整个当前画布填当前色(清屏) | ✅ 实现 |
| 56 | `vload_image` | `path_id[15:0] << 8 \| flags[7:0]` | 从路径表 path_id 读图, 解码成新画布并切换。flags: bit0=灰度 | 接口冻结(最小管线不解码) |
| 57 | `vscale` | `factor[15:0] << 8 \| 0` | 缩放标记: factor=256 表示 1.0×, 定点 8.8。接口冻结 | 接口冻结 |
| 58 | `vrotate` | `angle_deg[15:0] << 8 \| 0` | 旋转标记: 角度(0-359)。接口冻结 | 接口冻结 |
| 59 | `vtext_draw` | `text_id[15:0] << 8 \| size[7:0]` | 在画笔位置用当前色绘制文本表 text_id 的文本, 字号 size。接口冻结 | 接口冻结 |
| 60 | `vrender_ppm` | `out_id[15:0] << 8 \| fmt[7:0]` | 把当前画布按 fmt 渲染: fmt=0 → P6 二进制 PPM; fmt=1 → P3 文本 PPM。out_id=0 → 默认输出路径 | ✅ 实现(P6) |
| 61 | `vrender_png` | `out_id[15:0] << 8 \| 0` | PNG 渲染标记(需 zlib)。接口冻结 | 接口冻结 |
| 62 | `vflush` | 0(忽略) | 输出流刷新标记(强制物化) | ✅ noop |

### 3.1 路径表(path_id)与字符串问题

XL01 字节码是纯定长二进制, **不内嵌字符串**。文件路径 / 文本内容通过**旁挂路径表**解析:

- 前端发射字节码时, 同时生成一个 `*.vpaths.json` 旁挂文件(与 .xlbin 同目录), 内容:
  ```json
  { "paths": ["out/grad.ppm"], "texts": ["hello"] }
  ```
- `path_id` / `out_id` 是该表的整数下标。
- 最小验证中 `out_id=0` 直接映射到 `vis_front/out/` 下的默认文件名, 旁挂表可省略。
- 这条规则与 v0.1 "定长操作数杜绝解析歧义" 一致: 字符串不进指令流, 只进旁挂表。

### 3.2 画笔状态机

```
vcanvas_new(W,H)          → 画布分配, 画笔=(0,0), 颜色=黑(0,0,0)
vpen_move(X,Y)            → 画笔=(X,Y)
vpen_color(R,G,B)         → 颜色=(R,G,B)
vpix_dot / vpix_at / vfill_rect / vfill_all → 写画布
vpix_read                 → trace (R,G,B) at (X,Y)
vrender_ppm               → 物化画布到文件
```

越界规则(确定性硬错误, 不静默裁剪):
- (X,Y) 超出 [0,W)×[0,H) → 渲染器报确定性错误, 终止。
- `vfill_rect` 中 X1<X0 或 Y1<Y0 → 错误(不自动交换)。
- 未 `vcanvas_new` 就写像素 → 错误。

## 4. 与三符的关系

| 三符 | 在 v0.3 的投影 |
|------|---------------|
| `▸` 位置 | `vcanvas_new` 产生的画布 = 一个位置锚; `vload_image` 把外部文件锚成位置 |
| `↦` 变换 | 画笔状态(坐标/颜色)是变换参数; `vscale`/`vrotate`/`vtext_draw` 是变换接口 |
| `⟶` 流 | `vrender_ppm`/`vrender_png`/`vflush` 是块级流出——逐行写出, 不要求外部驻留整图 |

v0.3 **不新增三符符号**, 只把可视化算子挂到既有三符语义上。这符合 v0.1 "▸/↦/⟶ 接口签名冻结" 的铁则。

---

## 5. 确定性规则

1. **绘制顺序 = 指令流顺序**: 同一张画布, 两条等价指令流必须产生**逐字节相同**的 PPM。
2. **无运行时随机**: 可视化算子不引入任何运行时随机源。QReg(6) 是唯一熵源, 可视化不消费它。
3. **整数运算**: 所有像素计算用整数(R/G/B 各 0-255), 不归约、不浮点, 天然逐位一致。
4. **行优先扫描线**: `vfill_rect` / `vrender_ppm` 内部按行优先(从上到下, 每行从左到右)访问像素, 跨实现必须一致。
5. **多线程不影响**: 可视化渲染是单线程顺序执行(画布是共享可变状态, 禁止并行写)。这条与训练级"确定性并行"不冲突——可视化区域本就是 IO 顺序区。

## 6. 输出格式规范: PPM P6(最小可渲染格式)

PPM (Portable Pixmap) 是无外部依赖、纯文本头 + 二进制像素的最简图片格式。v0.3 选定 **P6 二进制**作为最小可渲染格式:

```
P6\n
<W> <H>\n
255\n
<W*H*3 字节 RGB 序列, 行优先, 从 (0,0) 左上开始>
```

- 魔数 `P6` 后跟换行; 宽高用 ASCII 十进制空格分隔; 最大亮度 `255`; 之后紧跟二进制像素。
- 每个像素 3 字节(R,G,B), 顺序行优先(y=0 顶行 → y=H-1 底行, x=0 左 → x=W-1 右)。
- P3 文本格式(fmt=1)作为可调试镜像, 同一字节码必须产出逐像素一致的 P3(仅头/编码不同)。

**验收**: 任何图像查看器/浏览器可直接打开 P6 PPM。Python 标准库无依赖即可写出(本工程实证)。

PNG(fmt=2, opcode 61)需 zlib 编码, v0.3 只冻结接口, 不要求最小管线实现。

## 9. 与既有 golden 的隔离

- v0.3 可视化算子 **不进入** 既有训练 VM(`xl_vm_train.c`)的算子分发表——执行器遇 opcode≥48 应报"可视化域, 转可视化渲染器", 不参与训练 golden。
- 既有五项哈希(字节码/预算/trace/归约浮点/loss序列)与汇合哈希 `6e7600a5f7a6dae6` **完全不动**。
- 可视化自己的 golden(未来): PPM 文件 sha256 + trace 哈希, 独立成 `golden/vis_golden.json`(本阶段先不锁, 等第二个可视化用例再定)。
