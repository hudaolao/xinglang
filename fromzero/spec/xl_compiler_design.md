# 星算语专用编译器 · 设计雏形（吸纳百家之长，避百家之短）

## 定位
星算语生态的**第一件自研工具**。gcc / rustc / dotnet 只是从零基座阶段的过渡脚手架——编译器、构建器、调试器最终都要长成星算语自己的。本期先落**编译器雏形**。

## 哲学：吸纳百家之长，避百家之短

| 源语言 | 其长（吸收进星算语编译器） | 其短（显式规避） |
|---|---|---|
| **C** | 零抽象、位置原生映射地址 → IR 直接映射内存布局 | 手动内存易悬垂/越界 → 编译器做所有权 + 边界分析，自动兜底 |
| **Rust** | 所有权/借用、编译期查悬垂 → 变换链所有权分析 | 借用检查过严、开发陡 → 编译器**自动推导**所有权，开发者免写 |
| **Lisp/Haskell** | 纯函数/惰性 → 变换即纯函数，惰性流显式化 | 运行时开销不可控 → 纯函数在**编译期**求值，惰性流折叠为块 |
| **Erlang** | 消息即计算、天然并发 → 流天然是消息通道 | 消息传递开销 → 编译器把流折叠为块级消息通道（⟶） |
| **APL/J** | 符号化数组、原语极简 → 三符▸↦⟶保留符号语义 | 符号过密可读性差 → 符号语义保留，但算子名显式 |
| **Q#** | 量子门即语言 → 变换链编译成确定性线路 | 抽象脱离经典硬件 → 门/变换可落经典 CPU，可复现 |

一句话：**把百家之长折叠进编译器本体，把百家之短在编译期消化掉**——开发者拿到的是一个既符号极简、又内存安全、又确定可复现的语言。

## 架构（三层）
- **前端**：词法(lexer) → 语法(parser) → AST
  - 三符 `▸ ↦ ⟶` 是**一等语法结构**
  - 每个 AST 节点带源位置（可诊断、可 trace）
- **中端**：语义分析 + 门禁（复用 Rust 校验器逻辑）+ IR 生成（XL01）
  - 三符顺序、资源预算、⟶ 禁全量驻留 → 编译期拦截
  - 输出 XL01 定长字节码（对接已建校验器/golden）
- **后端**（后续）：XL01 → 目标（经典 CPU / 存算一体 / 未来量子线路）

## 确定性铁律
- 同一源码 → 同一 XL01 字节码（确定性编译）
- 字节码 → 逐位一致执行（确定性并行）
- golden 哈希跨实现可回归

## 存算一体
- AST 节点类型即"存算一体"刻画：读取即计算（值在传输中已被运算）
- IR 的 `⟶` 块级流 = 存算一体在字节码层的体现
