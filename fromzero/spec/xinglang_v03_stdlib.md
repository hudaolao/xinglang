# 星算语 v0.3 · 标准库层(stdlib)规范(XL01 扩展)

> **里程碑**: P5 · 把星算语从「能训练」推进到「能干活」
> **铁则**: 不碰既有 17 算子, 不碰既有 golden, 新增一律 opcode≥18; 仍走统一 XL01 发射 + 可重放验收
> **哲学**: 存算一体 —— 读取即运算、运输即运算。stdlib 不是 C 标准库的照搬, 是把「读写/搬运/绑定」本身当成一等运算。

---

## 1. 版本说明

- v0.1 冻结 11 算子(张量内核 + 三符 noop 锚); v0.2 扩到 17 算子(训练级 IR)。
- v0.3 在此基础上**只增不改**: opcode 18~40 + 255 为 stdlib 标准库原语。
- 三符版本头 bump 为 **`[3,0,0]`**(v0.3 文件专用)。既有 v0.1=`[1,1,1]`、v0.2=`[2,0,0]` 的字节码文件**一字节不动**, golden 锁定的是文件本身, 不是版本号。
- 分层声明:
  - `xl_vm_train.c` 继续只负责训练算子(1~17), 跑训练 golden;
  - `xl_vm_stdlib`(本 spec 新执行器)负责干活算子(18~40,255);
  - 两执行器对 opcode 1~17 互为 trace 透传, 未来可合并为单 VM, 现在不合并以免动 golden。

## 2. v0.3 字节码文件格式(在 v0.1/v0.2 之上增量)

既有格式不变部分(前 7 字节 + 定长指令):

```
"XL01"(4B) | version(3B, v0.3=[3,0,0]) | 指令流(每条 4B = opcode(1B) + operand(3B, 小端))
```

v0.3 新增**指令流结束标记 + 常量段**(仅 v0.3 文件使用; v0.1/v0.2 文件不含, 旧执行器不受影响):

```
... 指令流 ... | halt(opcode=255, operand=0, 4B) | const_len(4B, u32 小端) | const_block(const_len 字节)
```

- 执行器从 offset=7 起逐条取指, 直到遇到 `opcode==255(halt)`; halt 即程序结束。
- halt 后紧跟 4 字节小端 u32 = 常量段字节数 `N`; 随后 `N` 字节为常量段。
- **常量段布局**: 连续若干条目, 条目编号 `k` 从 0 起递增; 每条目 = `(u32 小端 字节数 n)(n 字节 UTF-8 数据)`。字符串即 UTF-8 字节流, 不另设终止符(长度前缀自带边界)。
- operand(3B, 0~0xFFFFFF)即用来引用常量段条目号、寄存器、立即数。

> 为什么用 halt+长度前缀而不是改头部? 头部只有 3 字节版本号, 没有余量; 长度前缀段对旧执行器透明(旧文件根本没有 halt, 读到 EOF 即停)。这样 v0.3 扩展零侵入。

## 3. operand 编码约定(24 bit)

所有 stdlib 算子共用两套编码形态:

| 形态 | 24 bit 划分 | 用途 |
|------|------------|------|
| **单值** | `operand = V(24b)` | V 直接是常量段索引 / 立即数 / 目标指令号 |
| **双操作数** | `operand = (A:12b << 12) \| B:12b` | A、B 各 12 bit(0~4095); 寄存器编号取低 4 bit(0~15), 其余按算子定义作立即数 |

寄存器模型: VM 内置 **16 个通用寄存器 R0~R15**(4 bit 编码), 外加 PC、常量段指针、文件/数组句柄表。stdlib 结果默认写 R0, 与 train_front 的「结果落主寄存器」习惯一致。

|--------|------|------|------|---------------|----------------------------|
| 18 | `str_len` | 字符串 | 取常量段条目 k 的 UTF-8 字节长度 → R0 | 单值 = 条目 k | M=O(1), F=0, 带宽=O(n) 顺序读 n 字节 |
| 19 | `str_concat` | 字符串 | R0 串接 R1 → R0(新句柄) | 双值 A=R0src,B=R1src | M=O(a+b), F=0, 带宽=O(a+b) 一次写回 |
| 20 | `str_find` | 字符串 | 在 R0 源串中找常量段条目 k 模式串首个匹配位置 → R0(未命中=-1) | 单值 = 模式条目 k | M=O(1), F=O(比较次数), 带宽=O(n·m) 块级可剪 |
| 21 | `str_sub` | 字符串 | R0 源串取 [start, start+len) 子串 → R0 | 双值 A=start,B=len | M=O(len), F=0, 带宽=O(len) |
| 22 | `str_split` | 字符串 | 以常量段条目 k 分隔符切 R0 → R0=数组句柄 | 单值 = 分隔条目 k | M=O(k+1 段), F=0, 带宽=O(n) 一遍扫 |

| 25 | `arr_push` | 集合 | R0 数组尾追值 v | 双值 A=数组reg,B=v | M=摊还 O(1), F=0, 带宽=O(1) |

| 39 | `load_const` | 常量加载 | 把常量段条目 k 的内容句柄载入 R0(引用不拷贝, 存算一体) | 单值 = 条目 k | M=O(1,句柄), F=0, 带宽=0(只建引用) |

| 30 | `io_read_file` | IO | 读路径=常量段条目 k 的整个文件 → R0=内容句柄 | 单值 = 路径条目 k | M=O(filesize), F=0, 带宽=O(filesize) 顺序块读 |

## 5. 与三符(▸ ↦ ⟶)的关系

stdlib 不是三符之外的平行世界, 而是三符在「干活层」的落地:

- **`▸` 符号层 → `bind_addr`(35)**: ▸ 在训练层是 noop 符号锚; stdlib 把锚实体化——把一个数据句柄显式绑定到逻辑地址。「源头也是尽头」: 符号不再只是 trace, 而是可被 mmap_read/write(33/34) 寻址的真实入口。
- **`↦` 精度域 → 存算一体读**: stdlib 字符串/集合算子**禁止先拷贝再运算**。`str_len`(18) 在顺序读 n 字节的同一遍里计数(读取即运算), `str_find`(20) 在流扫中做比较(运输即运算)。不要求输入为全量驻留张量, 与 ↦ 的块级精神一致。
- **`⟶` 块级流 → IO 与遍历**: `io_read_file`(30)/`mmap_read`(33) 是块流——文件按块流入, 不强制全量驻留; `arr_iter_mark`(27) 是数组上的块流遍历标记, 与 ⟶ 的「禁全量驻留」铁则同源。

## 6. 确定性规则

1. **全整数/字节域**: stdlib 算子不引入浮点, 无浮点归约不确定性, 输出天然逐位确定。
2. **IO 是外部源**: `io_read_file`(30)/`io_read_line`(32) 的内容依赖外部世界, 非纯函数; 验收时在固定沙箱文件下重放, 文件内容本身进 trace 哈希。
3. **地址显式**: `mmap_read/write/bind_addr` 的地址必须由 operand 显式给出, 禁止隐式地址; 未 bind 的地址读 → 确定性错误(不是随机值)。
4. **控制流可重放**: `jmp/jmp_if_zero`(36/37) 的目标指令号是发射期静态定值, trace 记录每次跳转事件, 与训练 VM 的「算子事件序列进 trace 哈希」一致。
5. **并发**: stdlib 算子当前单线程语义; 未来并行化仍遵守「只改速度不改求值顺序」铁律。

## 7. 与既有 17 算子的兼容性声明(硬约束)

- **opcode 1~17 语义、编号、编码一字节不改**; v0.1/v0.2 的全部字节码文件(train_step.xlbin、各前端 sample.xlbin 等)字节不变。
- 新增只占 opcode 18~40 与 255, 与 1~17 无重叠。
- 既有 golden 哈希(多源头 `6e7600a5f7a6dae6`; 训练 VM 五项 `962f900298498478 / 901866b390bdd703 / e14bde70ae562db0 / 3a3ba78c9e7562a5 / bb742e7e70a1b970`)锁定的是既有文件, v0.3 新文件不动它们 → golden 不破坏。
- v0.3 执行器遇到 opcode 1~17: 仅记录 trace 事件并跳过(不执行训练数值), 训练数值仍由 `xl_vm_train.c` 负责。分层不混。
- 不启动 10M 真训, 不动 P4 BM25/⟶retrieve。

## 8. 验收

- stdlib 字节码可发射(头=XL01+[3,0,0], 含 halt+常量段)、可解析、可执行。
- 最小子集实证: `str_len`(18) + `io_print_str`(28) + `io_write_file`(31)/`io_read_file`(30) 各跑通, 输出可断言。
- 既有 CI(`_ci_all.py`)仍全绿: 11/11(多源头汇合) + 6/6(训练 VM golden)。
